# house of lore
本质是 `smallbin attack`，构造一个 `fake_chunk` 链来绕过 `smallbin` 中的链表完整性检查。
**使用条件**：
1. glibc 2.31 版本之下
2. 存在堆溢出 / 任意写漏洞，能够修改 Small Bin 中堆块的 bk 指针。
3. 能够在内存中构造并控制 fake chunk 的 fd / bk 指针。
4. 目标 fake chunk 所在内存区域可写，用来存放伪造的堆结构。
5. 程序会再次 malloc 对应大小的 Small Bin 堆块，触发分配流程。


正常情况下，`small bin`取出一个`chunk`的时候会从末尾取出，这个`victim`的`bk`指针指向的是倒数第二个`chunk`。此时检查`bck`的`fd`指针是否指向`victim`，通过检查后将`victim`取出，并将`bck`的`fd`指针指向`small bin`。若我们控制`victim`的`bk`指针，使其指向一个我们控制的`fake_chunk`，那么只需要控制该`fake_chunk`的`fd`指针指向了`victim`，这样以来便可以在取出`victim`的时候，将`fake_chunk`挂入`small bin`中。注意，取出`fake_chunk`的时候又需要经过`small bin`的检查，因此再此构造一个`fake_chunk2`，将`fake_chunk2`的`fd`指针指向`fake_chunk`，`fake_chunk`的`bk`指向`fake_chunk2`即可。

在 Glibc 2.27+ 引入 Tcache 后，经典 House of Lore 受限制。衍生出 _**Tcache Stashing Unlink**_。
在glibc 2.27 / 2.31 等较高版本的时候，会存在`tcache stash unlink`，我们可以先填满7个tcache，然后再使用smallbin attack。

## smallbin attack

**smallbin的结构**
small bin 是双向循环链表，链表头 `bin` 其实是 `main_arena.bins[]` 数组里的一项，被当作一个 `malloc_chunk` 来用。链表通过 `fd`（forward）和 `bk`（backward）串起来。chunk 内存布局：

```
偏移 0x00: prev_size
偏移 0x08: size
偏移 0x10: fd    <- 指向后一个 chunk
偏移 0x18: bk    <- 指向前一个 chunk
```
- `last(bin)` = `bin->bk`，取链表尾部那个 chunk（small bin 从尾部取出）
- 取出一个 chunk 时要做 脱链，把它从双向链表里摘掉


**smallbin的源码**：
```c
  if (in_smallbin_range (nb))
    {
      idx = smallbin_index (nb);
      bin = bin_at (av, idx);

      if ((victim = last (bin)) != bin)
        {
          if (victim == 0) /* initialization check */
            malloc_consolidate (av);
          else
            {
              bck = victim->bk;
	if (__glibc_unlikely (bck->fd != victim))
                {
                  errstr = "malloc(): smallbin double linked list corrupted";
                  goto errout;
                }
              set_inuse_bit_at_offset (victim, nb);
              bin->bk = bck;
              bck->fd = bin;

              if (av != &main_arena)
                victim->size |= NON_MAIN_ARENA;
              check_malloced_chunk (av, victim, nb);
              void *p = chunk2mem (victim);
              alloc_perturb (p, bytes);
              return p;
            }
        }
    }
```
思路是，通过修改某个 `smallbin chunk` 的 `bk` 指针指向目标地址 `target`，
劫持 malloc 流程，分配到攻击者指定地址的伪造堆块，从而实现任意地址读写。
每次从某个 `smallbin` 尾部拿出 `chunk` 时，会存在这个检查 `__glibc_unlikely (bck->fd != victim)` 需要绕过，因此需要在 `target` 处伪造 `fake_chunk` 使得 `fake_chunk->fd == victim`，同时由于最终要将 `target` 拿出来，还需要使得 `fake_chunk->bk` 的 `fd` 指向 `target`。

接着我们分析 `change_message` ，可以看到`change_message()` 首先通过 `%p` 直接泄露 `message` 的堆地址。
然后 `free(message)` 释放旧 message，但没有立即将 `message` 清空，导致 `message` 成为悬空指针。程序随后申请一个大小为 `[128,238]`的新 chunk，并在更新 `message` 指针之前再次执行 `read(0, message, 0x10)`，因此可以向已经释放的旧 chunk 写入 16 字节，形成 **UAF Write**。在 64 位环境下这 16 字节恰好可以对应修改 freed smallbin chunk 用户区开头的 `fd` 和 `bk` 指针。

我们可以通过这个函数构造 fake chunk来达到house of lore的效果，，最终控制 `pagelist`。
先伪造一条 **smallbin 双向链表**，让后面的 `malloc` 最终返回到 `.bss` 上的 `name` 附近，再通过写入 `.bss` 去覆盖 `pagelist`。

接着我们free掉chunk后，取出fack chunk，我们就可以返回到name了。

> [!NOTE] 返回地址
> malloc 返回地址
= fake_chunk + 0x10
= (name - 0x10) + 0x10
= name
 
>fake_chunk
    ↓
+0x00  prev_size   8字节
+0x08  size        8字节
+0x10  user_data   ← malloc  真正返回给程序的地址

这里前面需要有两个chunk，第二块大小可以为任意值，只是为了防止第一块free后与top chunk合并。



此时我们可以控制 `pagelist` 上的指针，但是程序并不可以直接泄露地址，可以考虑通过修改 `pagelist` 指向 `got` 表，修改 `free@got` 为 `puts@plt` 来 `leak`，拿到 `libc_base` 后再改为 `system_addr` 即可。
